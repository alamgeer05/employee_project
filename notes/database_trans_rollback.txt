1. WHAT IS A DATABASE TRANSACTION?
============================================================

A transaction is a group of database operations treated as
ONE UNIT.

The main idea:

Either all required database operations succeed,
OR the uncommitted changes are undone.

Example:

Create Employee
      ↓
Create Employee Profile
      ↓
Create Audit Record
      ↓
Everything successful?
   ↙              ↘
 YES              NO
 ↓                 ↓
COMMIT          ROLLBACK
 ↓                 ↓
Save all        Undo changes


Simple definition:

TRANSACTION =
A group of database operations that should be handled
together as one unit.


============================================================
2. WHY DO WE NEED TRANSACTIONS?
============================================================

Imagine:

Operation 1 → Create Employee
Operation 2 → Create Employee Profile
Operation 3 → Create Audit Record


Suppose:

Operation 1 → SUCCESS
Operation 2 → SUCCESS
Operation 3 → FAILURE


Without proper transaction handling:

Employee may exist
Profile may exist
Audit record may not exist


This can leave inconsistent data.


With a transaction:

Operation 1 → SUCCESS
Operation 2 → SUCCESS
Operation 3 → FAILURE
       ↓
   ROLLBACK
       ↓
All uncommitted changes are undone


This keeps the database consistent.


============================================================
3. MAIN SQLALCHEMY TRANSACTION METHODS
============================================================

The important methods are:

db.add()
db.flush()
db.commit()
db.rollback()
db.refresh()


They have different purposes.


============================================================
4. db.add()
============================================================

Example:

db.add(employee)


Meaning:

Add the SQLAlchemy object to the current session.


Important:

db.add() does NOT permanently save the data.


Mental model:

db.add()
   ↓
SQLAlchemy Session
   ↓
Waiting for database operation


Example:

employee = Employee(
    name="John",
    email="john@gmail.com"
)

db.add(employee)


The object is now associated with the session.


============================================================
5. db.commit()
============================================================

Example:

db.commit()


Meaning:

Commit the current transaction.

In simple terms:

"Save the current database changes permanently."


Flow:

db.add(employee)
      ↓
db.commit()
      ↓
Changes committed


After successful commit:

The transaction is completed.


============================================================
6. db.rollback()
============================================================

Example:

db.rollback()


Meaning:

Undo the uncommitted changes in the current transaction.


Example:

db.add(employee)

Something fails

db.rollback()


The pending transaction is rolled back.


IMPORTANT:

rollback() does NOT delete previously committed data.


Example:

Employee A
   ↓
commit()
   ↓
Saved permanently


Employee B
   ↓
operation fails
   ↓
rollback()


Result:

Employee A → ✅ Still exists
Employee B → ❌ Not saved


============================================================
7. db.refresh()
============================================================

Example:

db.refresh(employee)


Meaning:

Reload the object from the database.


Useful after commit when the database generates values
such as:

- ID
- timestamps
- database defaults


Example:

db.add(employee)
db.commit()
db.refresh(employee)


Now the Python object contains the latest database values.


============================================================
8. db.flush()
============================================================

Example:

db.flush()


Meaning:

Send pending changes to the database WITHOUT committing
the transaction.


It is useful when we need database-generated values before
the final commit.


Example:

db.add(employee)

db.flush()

print(employee.id)


Now the generated ID can be available while the transaction
is still not committed.


Important:

flush() ≠ commit()


flush():

Send pending SQL to database
but keep transaction open.


commit():

Commit transaction permanently.


Mental model:

db.add()
   ↓
Session
   ↓
db.flush()
   ↓
Database
   ↓
Transaction still open
   ↓
db.commit()
   ↓
Transaction committed


============================================================
9. COMMIT VS ROLLBACK VS FLUSH VS REFRESH
============================================================

+----------------+-------------------------------------------+
| Method         | Purpose                                   |
+----------------+-------------------------------------------+
| db.add()       | Add object to session                     |
| db.flush()     | Send pending changes without committing   |
| db.commit()    | Commit transaction permanently            |
| db.rollback()  | Undo uncommitted transaction changes      |
| db.refresh()   | Reload object from database               |
+----------------+-------------------------------------------+


============================================================
10. BASIC TRANSACTION PATTERN
============================================================

The most important pattern:

try:

    # Database operations

    db.commit()
    db.refresh(object)

except SQLAlchemyError:

    db.rollback()
    raise


Flow:

try
 ↓
Database operation
 ↓
commit()
 ↓
Success?
 ├── YES → refresh() → return
 │
 └── NO
      ↓
rollback()
      ↓
raise error


============================================================
11. WHY TRY / EXCEPT?
============================================================

Database operations can fail.

Examples:

- Duplicate value
- NOT NULL violation
- Foreign key violation
- Database connection problem
- Invalid database operation
- Constraint violation


If the database operation fails, we need to rollback the
transaction.


Example:

try:

    db.add(employee)
    db.commit()

except SQLAlchemyError:

    db.rollback()
    raise


============================================================
12. SQLAlchemyError
============================================================

Import:

from sqlalchemy.exc import SQLAlchemyError


Example:

try:

    db.add(employee)
    db.commit()

except SQLAlchemyError:

    db.rollback()
    raise


Why use SQLAlchemyError?

It catches SQLAlchemy/database-related errors.


You can technically use:

except Exception:


But for database-specific handling, SQLAlchemyError is more
appropriate.

13. PRACTICAL CREATE EMPLOYEE EXAMPLE
============================================================

Suppose our model is:

class Employee(Base):

    __tablename__ = "employees"

    id = Column(
        Integer,
        primary_key=True
    )

    name = Column(
        String,
        nullable=False
    )

    email = Column(
        String,
        unique=True,
        nullable=False
    )


Now create employee:

def create_employee(
    db: Session,
    employee: EmployeeCreate
):

    try:

        db_employee = Employee(
            name=employee.name,
            email=employee.email
        )

        db.add(db_employee)

        db.commit()

        db.refresh(db_employee)

        return db_employee

    except SQLAlchemyError:

        db.rollback()

        raise

============================================================

Step 1:

Create SQLAlchemy object.

Step 2:

Add object to session.

db.add(db_employee)


Step 3:

Commit transaction.

db.commit()


Step 4:

Reload database-generated values.

db.refresh(db_employee)


Step 5:

Return employee.

return db_employee


If something fails:

except SQLAlchemyError:

    db.rollback()
    raise

16. MULTIPLE OPERATIONS IN ONE TRANSACTION
============================================================

This is where transactions become really useful.


Suppose we need:

1. Create Employee
2. Create Employee Profile
3. Create Audit Record


We want all three to succeed together.


Example:

def create_employee_with_profile(db: Session):

    try:

        employee = Employee(
            name="John",
            email="john@gmail.com"
        )

        db.add(employee)

        db.flush()


        profile = EmployeeProfile(
            employee_id=employee.id,
            department="IT"
        )

        db.add(profile)


        db.commit()

        return employee


    except SQLAlchemyError:

        db.rollback()

        raise


============================================================
17. WHY flush() IS USED HERE
============================================================

After:

db.add(employee)


the employee ID may not yet be available.


We need:

employee.id


for:

profile.employee_id


So:

db.add(employee)

db.flush()

profile = EmployeeProfile(
    employee_id=employee.id
)


Now the generated employee ID can be used.


IMPORTANT:

flush() does NOT permanently commit the transaction.


The final:

db.commit()


still needs to happen.

============================================================

This is because the employee was not committed yet.

============================================================

Avoid directly returning:

- Database details
- File paths
- Internal implementation
- Sensitive technical information


Instead return a safe message.


Example:

    "message": "Internal server error"
}

============================================================
32. COMMON MISTAKES
============================================================

MISTAKE 1:

Calling commit() and forgetting rollback when an error occurs.


MISTAKE 2:

Thinking rollback() deletes previously committed records.


MISTAKE 3:

Thinking flush() is the same as commit().


MISTAKE 4:

Returning raw database exceptions to users.


MISTAKE 5:

Putting every database operation into separate commits when
they logically belong to one transaction.


MISTAKE 6:

Using BackgroundTasks for critical database operations.


MISTAKE 7:

Doing business logic directly inside the route instead of
keeping it in the service layer.

============================================================

You make several changes:

Change 2
Change 3

↓

↓
