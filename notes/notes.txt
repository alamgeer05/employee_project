---------------------
db: Session = Depends(get_db)

This is called Dependency Injection.

FastAPI sees:

Depends(get_db)

and thinks:

"Before calling register(), I need to execute get_db()."

So it goes to database.py.

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

Here's what happens:

Create a database session.
Pause at yield.
Give the session to the route.
After the route finishes, resume.
Execute db.close().

So when your route starts, it already has:

db

ready to use.

1. FASTAPI
----------

FastAPI is a Python framework used to build APIs.

It receives HTTP requests, processes them, and sends HTTP responses.

Basic application:

    app = FastAPI()

Run the application:

    uvicorn main:app --reload

3. ROUTER
---------

Router receives HTTP requests.

It defines API endpoints such as:

    GET /employees
    POST /employees
    POST /auth/register
    POST /auth/login

Example:

    @router.get("/employees")
    def get_employees():
        ...


Main.py registers the router:

    app.include_router(router)

Simple meaning:

    Router = receives the request and connects the request
    to the correct service/function.


4. SCHEMA
---------

Schema is used for API data validation.

Pydantic is used to create schemas.

Example:

    class UserCreate(BaseModel):
        username: str
        email: EmailStr
        password: str

The schema checks whether incoming data has the correct
structure and type.

Example:

    {
        "username": "Alam",
        "email": "alam@gmail.com",
        "password": "123456"
    }

If required data is missing or invalid, FastAPI returns
a 422 validation error.

Important:

    Schema = API data validation


5. RESPONSE SCHEMA
------------------

A response schema controls what data the API sends back.

Example:

    class UserResponse(BaseModel):
        id: int
        username: str
        email: EmailStr

It does NOT contain:

    hashed_password

So the password hash is not returned to the client.

Example:

    @router.post("/register", response_model=UserResponse)

This means the API response must follow UserResponse.


6. from_attributes
------------------

SQLAlchemy returns objects.

Pydantic schemas normally work with data structures.

    from_attributes = True

allows Pydantic to read values directly from a SQLAlchemy
object.

Example:

    db_user.id
    db_user.username
    db_user.email


7. MODEL
--------

A SQLAlchemy model represents a database table.

Example:

    class User(Base):
        __tablename__ = "users"

        id: Mapped[int] = mapped_column(...)
        username: Mapped[str] = mapped_column(...)
        email: Mapped[str] = mapped_column(...)
        hashed_password: Mapped[str] = mapped_column(...)

The model describes the structure of the database table.

Important:

    Model = Database table


8. SCHEMA VS MODEL
------------------

MODEL:

    Represents the database table.

SCHEMA:

    Validates API input and output.

Example:

    User model
        ↓
    PostgreSQL users table

    UserCreate schema
        ↓
    Validates registration request

    UserResponse schema
        ↓
    Controls registration response


9. SERVICE
----------

Service contains the business logic.

The router should not contain large database/business operations.

Example:

    def create_employee(db, employee):
        db_employee = Employee(
            name=employee.name,
            email=employee.email
        )

        db.add(db_employee)
        db.commit()
        db.refresh(db_employee)

        return db_employee

Router:

    return create_employee(db, employee)

Simple meaning:

    Router = receives request

    Service = performs the actual work

    Model = represents the database table


10. DATABASE.PY
--------------

database.py contains the setup required to communicate
with the database.

Main parts:

    DATABASE_URL
    engine
    SessionLocal
    Base
    get_db()


11. ENGINE
----------

Engine is SQLAlchemy's main connection manager for the database.

Example:

    engine = create_engine(DATABASE_URL)

It knows how SQLAlchemy should communicate with PostgreSQL.


12. SESSION
----------

A Session is used to interact with the database.

It is used for:

    db.add()
    db.query()
    db.commit()
    db.delete()
    db.refresh()

SessionLocal is a factory that creates database sessions.

    SessionLocal = sessionmaker(bind=engine)


13. BASE
--------

Base is the parent class for SQLAlchemy models.

Example:

    class Base(DeclarativeBase):
        pass

Then models inherit from Base:

    class User(Base):
        ...

    class Employee(Base):
        ...

This allows SQLAlchemy to understand the database models.


14. get_db()
-----------

get_db() creates a database session for an API request.

Example:

    def get_db():
        db = SessionLocal()

        try:
            yield db
        finally:
            db.close()

The session is created when needed and closed after
the request finishes.

This prevents database sessions from remaining open.


15. DEPENDS
----------

Depends is FastAPI's dependency injection system.

Simple meaning:

    "FastAPI, give my function something it needs."

Example:

    db: Session = Depends(get_db)

This tells FastAPI:

    Create a database session
    ↓
    Give it to this endpoint
    ↓
    Close it after the request

20. PASSWORD HASHING
--------------------

Passwords should NOT be stored directly in the database.

Instead:

    User password
         ↓
    password hashing
         ↓
    hashed password
         ↓
    Database

We use Passlib's CryptContext.

    pwd_context = CryptContext(
        schemes=["bcrypt"],
        deprecated="auto"
    )

Hash:

    pwd_context.hash(password)

Verify:

    pwd_context.verify(
        plain_password,
        hashed_password
    )

Important:

    Hashing = converting the password into a secure hash
    Verification = checking whether the entered password
                  matches the stored hash

22. JWT
-------

JWT stands for JSON Web Token.

JWT is used to identify/authenticate a user after login.

Login flow:

    User sends username/email + password
            ↓
    Database finds user
            ↓
    Password is verified
            ↓
    JWT is created
            ↓
    JWT is returned to client


23. JWT TOKEN
------------

When creating the token:

    create_access_token({
        "sub": db_user.email
    })

"sub" means subject.

In our project, the subject contains the user's email.

The token also contains an expiration time.

Example conceptually:

    {
        "sub": "alam@gmail.com",
        "exp": "expiration time"
    }


24. JWT REQUEST FLOW
-------------------

Client sends:

    Authorization: Bearer <JWT>

FastAPI receives the token.

    HTTPBearer
        ↓
    Extract token
        ↓
    verify_token()
        ↓
    Decode JWT
        ↓
    Get email from "sub"
        ↓
    Find user in database
        ↓
    Return current user


25. get_current_user()
----------------------

get_current_user() is used to protect endpoints.

Example:

    @router.get("/me")
    def read_current_user(
        current_user: User = Depends(get_current_user)
    ):
        return current_user

It means:

    Before allowing the endpoint to run,
    verify the JWT and find the user.

If the token is invalid:

    401 Unauthorized


26. PROTECTED ENDPOINT
----------------------

Example:

    @router.get("/employees")
    def get_employees(
        current_user: User = Depends(get_current_user),
        db: Session = Depends(get_db)
    ):
        return get_all_employees(db)

This endpoint requires:

    Valid JWT
    +
    Database session

-----------------------------

    OAuth2PasswordRequestForm

It reads login form data such as:

    username
    password

Important:

Our service checks:

    User.email == form_data.username
