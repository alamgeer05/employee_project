Docker Bind Mount — Short Notes
1. What is Bind Mount?

A bind mount connects a folder/file from your computer → container.

Your PC                    Docker Container
./cx_auth  ───────────────→ /app

Changes made on your PC are visible inside the container.

2. Syntax
volumes:
  - ./local-folder:/container-folder

Example:

services:
  auth-service:
    build: ./cx_auth
    volumes:
      - ./cx_auth:/app




| Part        | Meaning                 |
| ----------- | ----------------------- |
| `./cx_auth` | Folder on your computer |
| `/app`      | Folder inside container |
| `:`         | Maps one to the other   |


⭐ Remember this
volumes:
  - ./my-folder:/app

means:

"Take my local my-folder and mount it inside the container at /app."

Bind mount = Local folder ↔ Container folder.

DOCKER NETWORKING — SHORT NOTES

1. What is Docker Network?
Docker Network allows containers to communicate with each other.

2. Docker Compose Network
docker compose up automatically creates a network and connects all services.

Example:
services:
  api:
    ...
  db:
    image: postgres:16

api and db can communicate through the Docker network.

3. Why use "db" in DATABASE_URL?

DATABASE_URL=postgresql://postgres:root@db:5432/employee_db

Here:
db = PostgreSQL service name
5432 = PostgreSQL port

Docker automatically resolves "db" to the PostgreSQL container.

4. Why NOT localhost?

Inside the API container:

localhost = API container itself

So this is WRONG for container-to-container communication:

postgresql://postgres:root@localhost:5432/employee_db

Use:

postgresql://postgres:root@db:5432/employee_db

5. Easy Rule:

Your Computer → Container:
localhost:8000
localhost:5432

Container → Container:
service-name:port

Example:
API → PostgreSQL = db:5432

6. Remember:

localhost = myself
db = PostgreSQL container

Docker Compose automatically creates the network.

| 1  | What is Docker?                                   | Docker is a platform used to package and run applications in isolated **containers**.                                 |

| 3  | What is a Docker image?                           | An image is a **read-only blueprint/template** used to create containers.                                             |
| 4  | Image vs Container?                               | **Image = template**, **Container = running instance of that image**.                                                 |
| 5  | What is Dockerfile?                               | A Dockerfile contains instructions for building a Docker image.                                                       |

| 7  | Why use `docker compose up`?                      | It creates and starts the services defined in the Compose file.                                                       |
| 8  | Why use `docker compose up --build`?              | It **rebuilds the image first**, then starts the containers.                                                          |
| 9  | When do you need `--build`?                       | Usually after changing the **Dockerfile**, `requirements.txt`, or something copied into the image.                    |
| 10 | Do you need `--build` after changing Python code? | Not if the code is mounted using a **bind mount/volume**. Otherwise, usually yes.                                     |
| 11 | What is a Docker volume?                          | A volume stores data outside the container's writable layer so data can survive container recreation.                 |
| 12 | What is bind mount?                               | It maps a **host machine folder/file directly into a container**.                                                     |
| 13 | Why use bind mounts in development?               | Code changes on your computer become immediately available inside the container.                                      |
| 14 | Example of bind mount?                            | `volumes: - ./app:/app`                                                                                               |
| 15 | What does `./app:/app` mean?                      | Host's `app` folder → container's `/app` folder.                                                                      |
| 16 | What is `EXPOSE 8000`?                            | It documents that the application inside the container uses port `8000`.                                              |
| 17 | Does EXPOSE publish the port?                     | **No.** Port publishing is done using `ports`, e.g. `8000:8000`.                                                      |
| 18 | What does `8000:8000` mean?                       | Host port `8000` → container port `8000`.                                                                             |
| 19 | What does `WORKDIR /app` do?                      | Sets `/app` as the working directory inside the image/container.                                                      |
| 20 | What does `COPY . .` do?                          | Copies the current project files into the container's working directory.                                              |
| 21 | What does `COPY requirements.txt .` do?           | Copies `requirements.txt` into the current Docker working directory.                                                  |
| 22 | Why install requirements before `COPY . .`?       | Docker can **cache the dependency-installation layer**, making rebuilds faster when only code changes.                |
| 23 | What does `RUN` do?                               | Executes a command while **building the image**.                                                                      |
| 24 | What does `CMD` do?                               | Defines the default command that runs when the container starts.                                                      |

| 26 | Why `--host 0.0.0.0`?                             | It allows the application to accept connections from outside the container.                                           |
| 27 | What is `main:app`?                               | `main` = `main.py` module, `app` = FastAPI application object.                                                        |
| 28 | What is `depends_on`?                             | It tells Compose that one service depends on another service starting first.                                          |
| 29 | How does one container connect to another?        | Using the **service name** as the hostname, e.g. `postgresql://...@db:5432/employee`.                                 |
| 30 | Docker vs Virtual Machine?                        | Docker containers share the host OS kernel and are lightweight; VMs include a complete guest OS and are heavier.      |
